# 射电阵列二相校准 · 基组审计页

纯浏览器端运行的 TypeScript + React 审计工具：给定一组二相校准曝光（每条覆盖若干接收通道），
在 GF(2) 上选出与全部曝光张成**同一行空间**的基组——先**精确最小化总代价**，再按**标识升序
序列字典序最小**确定规范解，并把每条曝光归类为：

- **必选**：出现在所有最小代价基组中；
- **可选**：出现在部分（而非全部）最小代价基组中；
- **从不**：不出现在任何最小代价基组中。

页面联动展示覆盖矩阵、规范基组、消元主元见证（行最简形 + 主元列）、最小总代价与归属。
全部计算在浏览器本地完成，**无业务后端、无任何在线调用**。

## 输入规则

- 通道数：2–40 的整数（独立输入框）。
- 曝光：每行一条，格式 `标识 代价 覆盖向量`，共 2–160 条。
  - 标识：1–32 个可打印 ASCII 字符（不含空白），全局唯一；
  - 代价：正整数；
  - 覆盖向量：仅含 `0/1`、长度等于通道数、非全零。
  - 空行与 `#` 起首的整行注释被忽略。
- 非法输入原样保留，并按行号指出问题位置；存在问题时不出结论。
- 结论与录入顺序无关：同样的数据任意换行、乱序录入，结果完全一致。

## 算法说明

- 组合权重 `W(e) = cost(e)·K − 2^(M−rank_id(e))`（`K` 足够大）把「先最小化总代价、再取标识
  升序字典序最小基组」化为单一权重的最小权基问题；按 `(代价, 标识)` 升序的拟阵贪心即得规范解。
- 分类：对每条曝光 `e`，分别求「强制包含 `e`」与「强制排除 `e`」的最小代价基组，
  与全局最小代价比较即得必选 / 可选 / 从不。
- 主元见证：全部曝光的高斯-若尔当行最简形（与行序无关的规范形）及其主元列；
  页面同时校验规范基组消元得到同一最简形。

## 本地开发

```bash
npm ci
npm run dev        # 开发服务器
npm run test:run   # 单元测试（含暴力枚举对拍）
npm run build      # 类型检查 + 产物构建
```

## Docker 发布

静态站点由多阶段 `Dockerfile` 构建（Node 构建 → nginx 托管），经 Docker Compose 发布：

```bash
# 启动 Web（默认宿主机端口 8080，可用 WEB_PORT 覆盖）
WEB_PORT=9000 docker compose up --build web

# 健康检查
curl http://localhost:9000/health   # => ok
```

## 一次性核验服务 verify

`verify` 服务在容器内依次完成：代码测试（vitest）、构建检查（`tsc --noEmit && vite build`）、
对 `web` 服务的 HTTP 冒烟（`/health`、首页、静态资源），并以退出码判定成败。
测试用例覆盖**同代价基组分类**、**规范裁决**与**向量长度错误边界**（另含录入顺序无关性、
随机实例暴力对拍等）。

```bash
docker compose up --build --exit-code-from verify verify
echo $?   # 0 = 全部通过；非 0 = 任一环节失败
```
